# QidianCrawler

QidianCrawler 是一个面向 Windows 版 Chrome 和 Edge 的 Manifest V3 浏览器扩展。支持手动采集，也支持用户明确启动后按目标章数自动采集，并将批次导出为 UTF-8 TXT 或 JSON。

自动模式使用页面实际提供的“下一章”链接逐页处理，不轮询页面、不接管登录，也不会尝试操作或绕过滑块验证。仓库里的 `tools/` 和 `tests/` 仅用于开发校验与打包。

本项目只维护和验证 Windows 环境，不提供 macOS、iOS 或 Safari 适配与支持。

## 功能

* 手动采集当前章节。
* 输入 1–500 章启动自动采集，可随时停止，遇到验证时暂停并等待人工处理。
* 手动和自动模式都使用页面实际提供的“下一章”链接。
* 按采集顺序保存批次，并阻止重复章节和跨书混入。
* 自动模式达到目标后按所选格式逐章下载 TXT 或 JSON，手动导出按钮保留。
* 使用“书名-实际采集章数”命名目录，每个文件使用对应章节标题。
* 持久化结构化日志，并准确区分下载已接收、已完成、失败或取消。
* 提供中文诊断页、诊断报告和 DEBUG 日志开关。

## 安装到 Chrome

1. 在 Chrome 地址栏打开 `chrome://extensions/`。
2. 开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目的 `extension/` 目录，或选择打包生成的 `dist/QidianCrawler-v<版本>/`。
5. 如果安装或更新扩展时章节页已经打开，请刷新该页面一次。


Edge 的安装步骤相同，扩展管理地址为 `edge://extensions/`。Chrome 是主要支持目标，Edge 使用同一套扩展源码和 ZIP。

## 使用方法

### 手动模式

1. 在普通浏览器标签页中打开已经能够正常阅读的起点章节。
2. 点击扩展图标，再点击“采集当前章”。
3. 如需继续，点击“打开下一章”；正文显示后再次手动采集。
4. 选择 TXT 或 JSON，点击“导出”。
5. 确认不再需要当前批次后，再点击“清空当前批次”。

### 自动模式

1. 打开要作为起点的章节；已有同书批次会保留并计入目标章数。
2. 选择 TXT 或 JSON，输入 1–500 的目标总章数（含当前批次），点击“开始自动化”。
3. 需要中止时重新打开弹窗，点击“停止自动化”。
4. 遇到滑块验证时任务会暂停；在当前标签页手动完成后，重新打开弹窗并点击“继续自动化”。
5. 达到目标后，扩展会按章节分别下载所选格式。

自动任务运行时可以关闭弹窗。翻页前会等待 2 秒，并在章节页面内等待正文就绪；浏览器重启后任务不会继续，但已经加入批次的章节仍会保留。

扩展不会根据章节号猜测地址，章节顺序就是实际采集顺序。同一章节不会重复加入；切换到另一部书时，需要先导出或清空当前批次。

默认下载路径示例：

```text
Downloads/
└─ QidianCrawler/
   └─ 铁血残明-30章/
      ├─ 第145章 江徒.txt
      ├─ 第146章 暗流.txt
      └─ 第147章 夜雨.txt
```

书名和章节标题从当前章节页提取；这里的 `30` 是实际成功加入批次的章数。选择 JSON 时文件扩展名为 `.json`。浏览器开启“每次下载前询问保存位置”时，用户仍可自行修改保存位置和文件名。

## 导出格式

TXT 和 JSON 都按章节分别生成文件。TXT 写入书名、章节标题和正文段落，编码为 UTF-8；JSON 保留批次结构，但每个文件只包含一章：

```json
{
  "schemaVersion": 1,
  "kind": "qidian-manual-chapter-batch",
  "source": "qidian",
  "book": {
    "id": "1024424884",
    "title": "铁血残明"
  },
  "chapterCount": 1,
  "chapters": \\\[]
}
```

批次正文保存在 `chrome.storage.local` 中。项目设置了 6 MiB 的单批次安全上限，并在浏览器存储接近配额时提示先导出和清空。

## 日志与诊断

扩展弹窗右上角可以打开“日志与诊断”。每条持久日志都有固定字段：

```json
{
  "time": "2026-08-01T06:25:31.123Z",
  "level": "INFO",
  "code": "CHAPTER\\\\\\\_ADDED",
  "message": "章节已加入当前批次",
  "operationId": "capture-...",
  "details": {
    "chapterCount": 30,
    "paragraphCount": 42,
    "adapterId": "qidian"
  }
}
```

日志默认最多保留 500 条和 14 天，并限制在约 1 MiB 内。DEBUG 默认不持久化，需要时可在诊断页打开。

日志和诊断报告不会保存：

* 小说正文或完整 HTML；
* 书名、章节名、书籍 ID 或章节 ID；
* Cookie、令牌、密码或账号数据；
* 完整章节 URL、查询参数或 hash；
* 其他标签页的内容。

诊断页可以检查 Manifest、权限、本地存储、当前批次、TXT/JSON 生成、日志结构、下载 API，以及从弹窗进入诊断页之前的来源章节页。

## 权限

* `activeTab`：用户点击扩展时临时访问当前标签页。
* `scripting`：按用户操作注入章节提取器。
* `downloads`：下载 TXT、JSON 和诊断报告。
* `storage`：保存当前批次、自动任务状态、设置和结构化日志。
* `offscreen`：在后台生成并交给浏览器下载导出文件。

扩展不声明常驻站点权限、Cookie、网络拦截、历史记录、标签页列表或无限存储权限等，不包含主动网络请求代码。

## 测试

测试和打包不需要 npm、Node 或 Playwright，只需要 Python 3.10 以上标准库和本机 Chrome/Edge：

```powershell
python tools/check.py
```

该命令依次执行：

1. Manifest、权限、资源引用、UTF-8 和安全规则静态校验。
2. Python `unittest` 项目及可复现打包测试。
3. 使用本机 Chrome/Edge 无头模式打开 `tests/runner.html`，执行纯模块的真实 JavaScript、DOM 提取、批次、自动任务状态、TXT/JSON、文件名、日志轮转与测试。
4. 测试器会同时核对预期测试数、实际通过数和失败数，零项测试不会被判为通过。

需要指定浏览器时：

```powershell
python tools/check.py --browser "C:\\\\\\\\Program Files\\\\\\\\Google\\\\\\\\Chrome\\\\\\\\Application\\\\\\\\chrome.exe"
```

如果显式指定的浏览器路径无效，命令会立即失败。校验输出会列出实际使用的浏览器路径和可读取到的版本

若某些受限 Windows 环境无法创建 Chrome GPU 沙箱，测试器会先明确记录标准启动失败，再仅针对仓库中的本地合成测试页使用兼容参数重试

也可以直接用 Chrome 打开 `tests/runner.html` 查看逐项结果。这里运行的是普通页面环境中的核心模块单元测试。

## 打包

```powershell
python tools/package.py
```

打包器会先执行全部校验和测试，再生成：

```text
dist/
├─ QidianCrawler-v<版本>/
└─ QidianCrawler-v<版本>.zip
```

ZIP 中的 `manifest.json` 位于根目录，可作为扩展商店上传包；

## 项目结构

```text
extension/       Chrome/Edge 共用的扩展运行源码
tests/           Python 测试与浏览器内 JavaScript/DOM 测试
tools/           Python 标准库校验及可复现打包工具
dist/            本地生成的发布产物，不进入源码版本控制
```
